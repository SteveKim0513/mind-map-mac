# 0020. 보드는 절대좌표 자유배치 문서를 가진 세 번째 독립 파일 타입

날짜: 2026-09-03 · 상태: 채택

## 맥락

무드보드(자유 배치 캔버스) 기능을 추가하며 두 가지를 결정해야 했다: (1) 기존 마인드맵 캔버스를
확장해 자유배치 노드를 얹을지, 아니면 완전히 새 파일 타입으로 분리할지. (2) 실시간 협업이
핵심인 Miro 모델을 따를지, 로컬 전용인 Apple Freeform 모델을 따를지.

마인드맵을 확장하는 안은 `MindMapDoc.version` 스키마 변경과 마이그레이션이 필요하고, 트리
레이아웃(`treeLayout.ts`)과 절대좌표 자유배치가 같은 문서 안에서 충돌한다. Miro 모델은 실시간
멀티플레이어가 본질인데, 이 프로젝트의 불변 조건("사용자 데이터는 서버로 전송하지 않는다")과
정면으로 충돌한다.

## 결정

보드는 `.board` 확장자를 가진 **완전히 새로운 세 번째 파일 타입**(`BoardDoc`, `version: 1`)이다.
`.mind`/`.md`와 동일하게 워크스페이스 내 로컬 파일이 원본이며 서버 전송이 없다. 요소(텍스트,
스티키노트, 이미지, 도형, 연결선)는 트리 구조 없이 절대좌표(x, y, width, height)로 배치된다.
이미지 자산은 노트의 `.{stem}.assets/` 히든 폴더 관례(결정 0010)와 `images:write`/`images:read`
IPC를 그대로 재사용한다. 실시간 협업, 프레임/프레젠테이션 모드, 템플릿은 범위에서 제외한다
(Apple Freeform에 가까운 모델을 채택, Miro의 협업 중심 모델은 배제).

## 결과

기존 `MindMapDoc` 스키마와 트리 레이아웃 로직을 전혀 건드리지 않아 마이그레이션 리스크가 없다.
`io/`, `store/`, 도메인 모듈, 사이드바, 탭 관리 등 기존 3-way 확장 지점(`sessionStore.ts`의
`TabKind`, `Sidebar.tsx`의 파일 타입 분기 등)에 새 분기를 추가하는 반복 작업이 필요하다. 이미지
자산 IPC를 재사용하는 대신 `electron/main.ts`의 확장자 하드코딩 지점(버전 검증, 트리 워커,
rename/trash) 다수에 `.board` 케이스를 추가해야 한다.
