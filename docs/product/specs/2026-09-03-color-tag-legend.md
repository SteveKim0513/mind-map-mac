# 색상 태그 범례 — 기획서

> 작성: 2026-09-03 · 상태: 초안
> 출처: 사용자 요청 — "마인드맵마다 컬러 블럭 메타데이터(빨강=새 아이디어, 노랑=진행 중인 일 같은 태그)를 만들고, 경로 표시줄 아래 같은 높이에 노출, 클릭하면 필터되게. 기존 하단 색상 필터와 중복이면 대체해도 된다."
> 관련: [[color-system]], 결정 0001(시맨틱 컬러 키), FEATURE-INVENTORY.md 5절(보기·필터) — "색상 필터는 색이 하나도 안 쓰인 맵에서는 도트가 숨겨져 발견성이 낮다"는 기존 한계.

## 1. 문제 (Why)

노드 색은 이미 8개 시맨틱 키(빨강 계열은 로즈로 분리·주황·노랑·초록·틸·보라·핑크·브라운)로 지원되고, 하단 캔버스 툴바에 "이 맵에 쓰인 색"을 점으로 보여주는 필터도 있다. 하지만 **그 색이 무슨 뜻인지는 사용자 머릿속에만 있다.** 맵마다(프로젝트마다) 색의 의미가 다를 수 있는데(이 맵의 빨강 = 새 아이디어, 저 맵의 빨강 = 막힘) 이를 기록할 곳이 없어 시간이 지나면 본인도 잊는다.

부수적으로 기존 색상 필터는 **발견성이 낮다** — 색이 하나도 안 쓰인 맵에서는 필터 UI 자체가 사라져(도트가 없으므로) 기능이 있다는 걸 알 방법이 없다(FEATURE-INVENTORY 5절 "알려진 한계"). 이번 기획은 "색에 이름 붙이기"와 "그 필터 UI의 발견성 개선"을 한 번에 해결한다.

## 2. 해결 (What)

**경로 바(`PathBar`) 바로 아래, 같은 높이(22px)로 "태그 바"를 새로 둔다.** 이 맵(.mind 파일)에서 정의된 색상 태그를 칩(점 + 라벨)으로 나열하고, 칩을 클릭하면 그 색으로 캔버스를 필터링한다. 하단 캔버스 툴바의 기존 색 점 필터는 **제거하고 이 바로 대체**한다(기능 중복 — 사용자 요청대로 대체).

### 레이아웃

```
┌ tab-strip ────────────────────────────────────────────────┐
├ pathbar  (22px) 워크스페이스 › 프로젝트 › 기획.mind          ┤
├ tagbar   (22px) ● 로즈 새 아이디어   ● 노랑 진행 중    ＋    ┤
├──────────────────────────────────────────────────────────┤
│                        canvas                              │
│                                                    [− 100% +]│ ← 하단 툴바: 줌/팬/재배치만 남음
└──────────────────────────────────────────────────────────┘
```

필터가 활성화된 상태(예: "로즈" 클릭):

```
├ tagbar  [●로즈 새 아이디어]  ● 노랑 진행 중     상위 ⌄ 하위 ⌄  ┤
```
(활성 칩은 눌린 상태로 강조, 그 옆에 기존 "상위/하위 포함" 토글이 그대로 인라인 노출)

### 진입점 · 핵심 동작

- **칩 표시 대상**: 이 문서에서 (a) 실제 노드에 쓰인 색, **또는** (b) 라벨이 정의된 색(아직 안 썼어도) — 둘의 합집합을 `TAG_KEYS` 순서로 나열. 즉 라벨을 미리 정의해두면 노드에 색을 칠하기 전부터 칩이 보인다.
- **필터 토글**: 칩(점+라벨 영역) 클릭 = 기존 `colorFilter` 토글과 동일 동작(다시 클릭하면 해제). 활성 시 "상위 포함/하위 포함" 토글이 칩 옆에 그대로 노출(기존 로직 이식, 변경 없음).
- **라벨 새로 정의 — "＋" 버튼**: 바 오른쪽 끝에 항상 아이콘 전용 "＋"가 있다(칩이 하나도 없는 빈 맵에서도 보임 → 발견성 확보). 누르면 아직 라벨이 없는 나머지 색 키를 작은 팔레트로 보여주고, 하나 골라 라벨 텍스트를 입력 → Enter로 확정, Esc로 취소.
- **라벨 수정 — hover 펜슬**: 칩에 마우스를 올리면 오른쪽에 작은 펜슬 아이콘이 나타난다(클릭 영역을 필터 토글과 분리하기 위해 hover 시에만 노출). 펜슬 클릭 → 칩 안 텍스트가 인라인 입력으로 바뀜 → Enter/blur로 저장(undo 가능), Esc로 취소. 라벨을 빈 문자열로 저장하면 기본 이름으로 되돌아간다(태그 자체는 사라지지 않음 — 사용 중이면 계속 칩으로 남음).
- **기본 이름**: 라벨을 아직 안 정한 색도 칩엔 항상 읽을 수 있는 이름이 있어야 한다 → 8개 키에 한국어 기본 이름 부여(로즈·주황·노랑·초록·틸·보라·핑크·브라운). `theme/palette.ts`에 `TAG_DEFAULT_LABELS` 상수로 추가.
- **분할 보기**: `PathBar`와 동일하게 좌/우 각자의 열린 맵 문서 기준으로 독립된 태그 바를 표시.
- **맵이 아닌 탭(노트·캘린더)에서는 태그 바 자체를 숨긴다(높이 0)** — 경로 바처럼 빈 자리를 유지하지 않는다. 판단은 **행 단위**: 분할 보기에서 좌/우 중 **한쪽이라도 맵**이면 행(22px)은 유지하고 맵이 아닌 쪽만 그 절반이 빈 상태, 좌/우 **둘 다 맵이 아니면 행 전체가 사라진다**(캔버스가 그만큼 위로 올라옴). 단일 탭(분할 아님)일 때는 맵 탭에서만 보이고 노트·캘린더 탭에서는 완전히 사라진다.

### 정렬·톤 원칙 (디자인)

- 칩은 경로 바의 crumb과 같은 밀도(11px 라벨, 컴팩트 padding)로 — 새 UI 요소가 아니라 경로 바의 "형제 줄"처럼 보이게.
- 점(dot)은 기존 `--tag-*` 파스텔 값을 그대로 재사용(새 색 추가 없음 — 결정 0001 유지, 아래 3절 참고). 라벨 텍스트는 `--ink-muted`, 활성 칩만 `--ink`+옅은 배경으로 강조(선택 상태 표현은 기존 `filter-dot.on`과 동일한 강도).
- 모션은 펜슬 인라인 편집 전환 정도만, ≤120ms — 앱 전반의 절제된 모션 톤 유지.

## 3. 데이터 모델 / 구조 변경 (How)

- `MindMapDoc`에 옵션 필드 추가: `tagLabels?: Partial<Record<TagKey, string>>` — 문서(.mind 파일)마다 독립 저장. 다른 맵과 공유되지 않는다(요청대로 "이 맵에서" 정의).
- **버전 무범프**: 옵션·가산 필드이므로 `durationMin`/`allDay` 선례([decisions/0012](../../decisions/0012-node-duration-field.md))를 따라 `MindMapDoc.version`(현재 `1`) 변경 없이 추가 가능. 필드가 없는 레거시 문서는 빈 객체로 취급.
- `src/io/formats.ts` 로드 경계에서 검증: 알 수 없는 키는 버리고 `TAG_KEYS`에 속한 키만 통과(외부 입력은 `io/` 경계에서 검증하는 기존 규칙).
- `src/theme/palette.ts`에 `TAG_DEFAULT_LABELS: Record<TagKey, string>` 추가(8개 기본 한국어 이름) — 태그 바뿐 아니라 향후 노드 색상 피커의 툴팁에도 재사용 가능.
- `mapStore.ts`에 `setTagLabel(key: TagKey, label: string)` 액션 추가 — 기존 `_pushHistory` 패턴으로 undo 가능한 문서 메타 편집으로 취급(다른 문서 메타 편집과 동일 취급).
- 기존 `colorFilter` state/액션(`mapStore.ts`), `treeLayout.ts`의 forest 필터링 로직은 **변경 없음** — UI만 하단 툴바(`Pane.tsx`)에서 새 `TagBar`(`src/panes/TagBar.tsx`, `PathBar.tsx` 형제)로 이전.
- `Pane.tsx`의 기존 `usedColors`/`filter-dots`/상위·하위 토글 블록(대략 L157-192)은 제거하고 `TagBar`로 옮긴다. 하단 툴바는 줌/팬/재배치만 남는다.
- `App.tsx`에서 `<PathBar .../>` 바로 아래 `<TagBar leftTab rightTab split .../>`를 형제로 마운트(경로 바와 동일한 props 패턴).

## 4. 범위에서 뺀 것 (Not now)

- **다중 색 동시 필터(OR 조건)** — 지금도 `colorFilter`가 단일 값이라 이번에도 단일 선택 유지. 여러 색 동시 필터는 후속.
- **8개 키 확장이나 커스텀 hex 허용** — 결정 0001은 유지. 이번 기획은 "이름(라벨)"만 커스텀이고 색상 값 자체는 고정 팔레트 그대로. (결정 0001의 "커스텀 색 요구가 생기면 재검토" 조항 중 색상값 자체 커스텀은 여전히 다루지 않음 — 필요 시 별도 논의.)
- **라벨의 문서 간 공유/전역 프리셋** — 지금은 맵(파일)마다 독립. 워크스페이스·폴더 단위 공유 프리셋은 후속(수요 확인 후).
- **노드 색상 지정 팝오버(피커)에 라벨 노출** — 관련 있지만 별도 컴포넌트라 이번 범위에서 분리. 후속 스펙에서 다룰 수 있음(피커 스와치에 라벨을 툴팁으로 보여주면 "칠하기 전에 뜻을 확인"할 수 있어 가치 있음).
- **태그별 노드 개수 배지** — 발견성 2단계 개선으로 후속.
- **"상위/하위 포함" 토글 자체의 재설계** — 기존 동작을 그대로 옮기기만 한다.

## 5. 완료 기준 (Done when)

- [ ] 경로 바 바로 아래, 같은 높이(22px)에 태그 바가 렌더된다(맵 탭에서)
- [ ] 이 맵에서 사용 중이거나 라벨이 정의된 색이 칩(점+라벨)으로, `TAG_KEYS` 순서로 나열된다
- [ ] "＋"로 아직 라벨이 없는 색 키를 골라 새 라벨을 정의할 수 있다 — 빈 맵(사용 색 0개)에서도 "＋"는 항상 보인다
- [ ] 칩 hover 시 펜슬 아이콘으로 라벨을 인라인 수정할 수 있고, undo/redo로 되돌릴 수 있다
- [ ] 칩(펜슬 제외 영역) 클릭이 기존 `colorFilter`를 토글한다 — 활성 시 상위/하위 포함 토글이 동일하게 동작
- [ ] 하단 캔버스 툴바의 기존 색 점 필터 UI(`usedColors`/`filter-dots`)는 제거됐다(중복 대체 완료)
- [ ] 분할 보기에서 좌/우가 각자의 맵 문서 기준으로 독립적인 태그 바를 표시한다; 한쪽만 맵이면 그 쪽만 보이고 반대편은 빈 상태
- [ ] 맵이 아닌 탭만 열려 있을 때(단일 탭, 또는 분할 양쪽 다 비-맵)는 태그 바 행 자체가 사라진다(22px 자리 차지 안 함) — 경로 바와 달리 빈 자리를 남기지 않는다
- [ ] `tagLabels`는 옵션 필드로 저장/로드되고, `version` 무범프이며 레거시 문서(필드 없음)가 정상 로드된다
- [ ] `docs/product/FEATURE-INVENTORY.md` 5절(보기·필터) 갱신 — 기존 "발견성 낮음" 한계 서술 제거/수정
- [ ] `src/ui/Manual.tsx`(사용 안내) 갱신
- [ ] `e2e/*.spec.ts`에 `@map` 태그로 핵심 시나리오 추가: 라벨 정의 → 칩 표시 → 클릭 필터 토글 → 상위/하위 포함 → 라벨 인라인 수정

## 6. 의존성 · 참고

- 재사용(변경 없음): `mapStore.ts`의 `colorFilter`/`setColorFilter`, `treeLayout.ts`의 forest 필터링. 이번 기획은 진입점 UI 이전 + 라벨 레이어 추가일 뿐, 필터링 알고리즘은 손대지 않는다.
- 결정 0001과의 관계: 라벨은 키에 대한 별칭일 뿐 팔레트(8키/hex 값) 자체는 불변이므로 결정 0001을 뒤집지 않는다. 다만 "커스텀 색 요구가 생기면 재검토"라는 문구가 이번 기획으로 부분적으로(이름만) 해소된다는 점을 결정 문서에 각주로 남기는 걸 권장.
- **벤치마크**:
  - **Trello 라벨**: 카드 라벨은 색+이름을 가지며, 카드 hover → 펜슬 아이콘 → 이름 편집(색과 이름 편집이 분리된 소진입점), 클릭/단축키로 필터. 이번 기획의 "hover-pencil로 편집, 클릭으로 필터"는 이 패턴을 그대로 따온 것 — 클릭 한 번의 의미(필터)가 편집으로 오염되지 않는다는 게 검증된 이점.
  - **Notion select/multi-select 속성**: 옵션(색+이름)이 데이터베이스(문서) 단위로 로컬 정의되고 공유되지 않는다 — "맵마다 독립적인 태그 정의"라는 이번 스코프 결정의 근거.
  - **차이점**: Apple 미리알림/메모의 색 플래그는 이름이 없다(색만) — 바로 이 "이름 없음"이 사용자가 이번에 명시적으로 불편함을 느낀 지점이라 참고하지 않음.
