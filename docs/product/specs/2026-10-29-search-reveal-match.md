# 검색 결과 위치로 이동 — 기획서

> 작성: 2026-10-29 · 상태: 출시됨(구현 완료, 릴리즈 전) · 결정 6절: 두 항목 모두 권장안으로 합의
> 출처: 사용자 요청 — "검색을 하면 그 검색된 파일이 열리는데 그 검색된 내용에 표시가 되거나 그 위치로 스크롤 하거나 그 단어가 여러개면 다음으로 진전할 수 있도록 해줘."
> 관련: FEATURE-INVENTORY.md 9절(검색), `src/search/GlobalSearch.tsx`, `src/search/Search.tsx`(맵 안 찾기 바)

## 1. 문제 (Why)

전체 검색(⌘⇧F, 노트·홈에서 ⌘F)에서 결과를 고르면 **노트는 파일을 열기만 한다.** 검색어가 본문 어디에 있는지 표시도, 스크롤도 없어서 긴 노트에서는 사용자가 다시 눈으로 찾아야 한다. 같은 단어가 여러 번 나오면 다음 위치로 넘어갈 방법도 없다(노트에는 찾기 기능 자체가 없다 — 인벤토리 9절 "노트 ⌘F 불가").

맵·보드 결과는 이미 해당 노드·스티키를 선택하고 화면 가운데로 옮긴다. 하지만 검색어가 그 맵의 다른 노드에도 있을 때 이어서 볼 방법이 없고, **접힌 가지 아래 노드는 이동이 조용히 실패한다**(선택만 되고 화면에 안 보임).

강화하는 핵심 경험: **속도** — 찾은 것을 다시 찾지 않게.

## 2. 해결 (What)

검색 결과를 고르면 **연 파일 안에서 검색어를 이어받은 "찾기 바"가 뜬다.** 맵에 이미 있는 찾기 바(`n/m`, ↑↓, Esc)와 같은 모양·같은 키로 통일한다.

### 노트 (이번 작업의 중심)

```
┌ 노트 탭 ──────────────────────────────────────────────┐
│                             [ 회의록      2/5  ↑ ↓ ✕ ] │ ← 찾기 바 (오른쪽 위)
│  ...지난주 ▓회의록▓ 정리하면서...                      │ ← 모든 일치: 연한 강조
│  ...                                                   │
│  ...이번 █회의록█ 에서 결정한...                       │ ← 현재 일치: 진한 강조 + 화면 가운데
└────────────────────────────────────────────────────────┘
```

- 결과를 고르면 노트가 열리고, 본문의 **모든 일치를 연하게, 현재 일치를 진하게** 칠한다. 첫 일치(문서 순서)가 화면 가운데에 오도록 스크롤한다.
- **Enter / ↓ = 다음, ⇧Enter / ↑ = 이전**, 끝에서 처음으로 순환. 카운트 `2/5` 표시.
- 찾기 바 입력창에서 검색어를 고치면 그 자리에서 다시 찾는다.
- **Esc** 또는 ✕ = 바 닫기 + 강조 모두 제거, 커서는 현재 일치 위치에 둔다(바로 이어 쓰기 가능).
- 본문을 편집해도 바는 유지되고 일치는 다시 계산된다.
- 일치 규칙은 전체 검색과 같다: 대소문자 무시 부분 문자열. 화면에 보이는 텍스트 기준(마크다운 기호는 대상 아님).
- 제목·양식 값에서만 일치하고 본문에는 없으면: 바는 "없음"을 보여 주고 스크롤하지 않는다.
- **노트에서 ⌘F도 이 찾기 바를 연다**(지금은 전체 검색으로 넘어감). 전체 검색은 ⌘⇧F로 그대로 쓴다. → 맵과 같은 규칙("⌘F = 이 파일 안, ⌘⇧F = 전체")으로 통일. *[결정 필요 — 6절]*

### 맵

- 결과를 고르면 지금처럼 노드로 이동하고, 추가로 **기존 맵 찾기 바를 검색어가 채워진 채로 연다.** 그 맵의 일치 노드가 모두 강조되고, 고른 노드가 현재 일치(`k/m`)가 된다. Enter로 다음 노드.
- 이동 대상 노드가 **접힌 가지 아래면 조상을 펼친 뒤** 가운데로 옮긴다(현재 실패하는 경우 수정).

### 보드

- 지금처럼 스티키를 선택하고 가운데로 옮긴다(변경 없음). 찾기 바는 이번 범위에서 뺀다 — 3절.

### 기타 규칙

- undo 대상 아님(강조는 화면 표시일 뿐 문서를 바꾸지 않는다). 파일 포맷·리마인더 동기화 영향 없음.
- 공유 폴더 노트(실시간 공동편집)도 같은 동작. 내용이 릴레이에서 늦게 도착하므로, 내용이 채워진 뒤에 찾는다.
- 노트를 열 때 마지막 스크롤 위치를 복원하는 기존 동작보다 **검색 이동이 우선**한다.

## 3. 범위에서 뺀 것 (Not now)

- **보드 안 찾기 바** — 보드에는 찾기 기능 자체가 없어 새로 만들어야 한다. 스티키 이동은 이미 된다. 쓰임이 확인되면 별도 기획.
- **바꾸기(찾아 바꾸기)** — 요청 범위 밖.
- **대소문자 구분·정규식·단어 단위 옵션** — 전체 검색에도 없다. 단순함 유지.
- **노드 메모(note 필드)·링크 안의 위치 강조** — 맵에서는 노드 단위로 강조한다(지금 맵 ⌘F와 같음).
- **분할 화면 두 칸에서 동시에 다른 찾기** — 맵 강조 상태가 전역 하나라 마지막 찾기가 이긴다(지금도 같음).

## 4. 완료 기준 (Done when)

- [ ] 전체 검색에서 노트 결과를 고르면 모든 일치가 강조되고 첫 일치로 스크롤된다
- [ ] 노트 찾기 바에서 Enter/⇧Enter/↑↓로 일치 사이를 순환하고 `n/m`이 맞게 바뀐다
- [ ] Esc로 바가 닫히고 강조가 모두 사라진다
- [ ] (결정 시) 노트에서 ⌘F가 노트 찾기 바를 연다
- [ ] 맵 결과를 고르면 맵 찾기 바가 검색어와 함께 열리고 Enter로 다음 노드로 간다
- [ ] 접힌 가지 아래 노드도 펼쳐져 화면 가운데에 온다
- [ ] 공유 폴더 노트에서도 동작한다
- [ ] E2E(`@note @nav`, `@map @nav`) 추가, 일치 계산은 단위 테스트

## 5. 구현 메모 (개발자용)

- 전달 경로: `uiStore`에 `revealReq: { path, query, nonce }` 하나를 둔다. `GlobalSearch.choose`가 설정하고, 연 탭(노트 `NotePane` / 맵 `App`의 Search)이 소비한다. 도메인끼리 직접 부르지 않는다(기존 `focusReq` nonce 패턴).
- 노트 강조: `wikiLink.ts`와 같은 방식의 ProseMirror Decoration 확장(`searchHighlight`)을 `buildNoteExtensions`의 `extras`로 넣는다. 일치는 마크다운 문자열이 아니라 **에디터 문서(텍스트 노드)를 직접 훑어** 계산한다 — 순수 함수로 분리해 단위 테스트.
- 스크롤: 목차 이동(`NotePane.goHeading`)과 같은 방식. `NoteEditor`의 스크롤 위치 복원(마운트 시·이미지 치환 후)이 덮어쓰지 않게 순서를 잡는다.
- 맵: `Search`에 `initialQuery`·`initialActiveId` prop. 노드 이동 전 접힌 조상 펼치기는 `mapStore`에 액션으로.
- 새 Tiptap 확장이므로 구현 전 `docs/exec-plans/active/`에 계획 작성.

## 6. 결정 필요

1. **노트에서 ⌘F를 "이 노트 안 찾기"로 바꿀까?** 권장: 예. 맵과 규칙이 같아지고, 전체 검색은 ⌘⇧F로 남는다. 바꾸지 않으면 찾기 바는 전체 검색에서 들어올 때만 뜬다.
2. **보드 찾기 바는 이번에 뺄까?** 권장: 뺀다(3절).
