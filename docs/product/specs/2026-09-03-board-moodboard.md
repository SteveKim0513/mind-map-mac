# 보드(무드보드) — 기능 명세

> 작성: 2026-09-03 · 작성자: Claude (세션 합의) · 상태: 출시됨
> 규칙: 이 1페이지가 합의되기 전에 개발을 시작하지 않는다. 4개 항목을 넘는 분량이 필요하면 그때 늘린다.

## 1. 문제 (Why)

마인드맵(구조화된 트리)과 노트(순수 텍스트)만으로는 이미지·짧은 메모·아이디어 조각을 자유롭게
흩어놓고 배치를 눈으로 재구성하는 작업(무드보드, 레퍼런스 모음, 러프 스케치)을 할 수 없다.
Apple Freeform처럼 제약 없는 자유 배치 캔버스가 필요하되, 이 앱의 핵심 경험인 "소유"(로컬 파일,
서버 없음)를 그대로 유지해야 한다. Miro류의 실시간 협업/퍼실리테이션 기능은 서버 없음 불변
조건과 충돌하므로 대상이 아니다.

## 2. 해결 (What)

새 파일 타입 `.board`를 `.mind`/`.md`와 나란히 사이드바에 세 번째 파일 타입으로 추가한다.
**v1 실사용 피드백(2026-09-03)으로 "스티키노트 + 화살표" 중심으로 재정의**했다 — 도형/텍스트
박스는 제거하고, 화살표는 항상 요소를 잇는 연결로만 존재한다(Miro/Freeform과 동일한 모델).

- 진입점: 사이드바 "새 보드" 메뉴/버튼(빈 워크스페이스 CTA 포함), 새 파일 생성 시 `.board` 확장자로 저장.
- 핵심 동작 규칙:
  - 요소는 절대 좌표(x, y, width, height)로 자유 배치. 트리 레이아웃 없음.
  - 요소 타입은 **`sticky`(스티키노트) · `image`(워크스페이스 내 `.{stem}.assets/` 폴더에 파일로
    저장, 문서엔 상대 경로 참조만) · `connector`(화살표)** 세 가지뿐. 독립된 텍스트 박스·도형은
    없다(§3).
  - **화살표는 항상 두 요소에 id로 연결된다** — 자유 좌표를 갖지 않고, 어느 한쪽이 움직이면
    렌더 시점에 다시 계산되어 함께 따라간다. 스티키/이미지를 선택하거나 hover하면 상하좌우
    4개의 연결 포인트가 나타난다: **클릭**하면 그 방향에 새 스티키가 자동 생성되고 화살표로
    연결된 채 바로 편집 모드로 들어간다(마인드맵의 Tab/Enter로 자식·형제 노드를 만드는 흐름과
    같은 사고). **드래그**해서 기존 스티키/이미지에 놓으면 그 대상과 연결하고, 빈 캔버스에
    놓으면 그 자리에 새 스티키를 만들며 연결한다 — 화살표가 어느 경로로도 결국 연결로 끝나게
    설계했다.
  - 스티키노트는 **색**(마인드맵 노드와 같은 태그 팔레트, `theme/palette.ts`)과 **모양**(사각형·
    타원 2종) 두 축을 독립적으로 가진다. 둘 다 마인드맵의 색 필터와 같은 방식으로 "이 값만 보기"
    필터가 가능하다(선택하면 다른 스티키가 흐려짐, 하단 툴바).
  - 스티키를 선택하면 **마인드맵 노드 선택과 같은 방식으로 그 위에 플로팅 메뉴**가 뜬다(하단
    툴바가 아니라 `canvas/SelectionToolbar.tsx`와 동일한 패턴, `.sel-toolbar`/`.st-*` 클래스
    공유) — 색 변경·모양 변경·정렬(가로 왼쪽/가운데/오른쪽 + 세로 위/중간/아래 한 플라이아웃)·
    글자 서식(크기 소/중/대, 굵게)·텍스트 박스 추가.
  - **텍스트 박스 추가**: 스티키 카드 **바깥쪽 아래**에 새 텍스트 블록이 쌓인다(카드 내부가
    아니라 카드와 별개의 작은 블록으로, 여러 개를 계속 추가하면 아래로 쌓임 — 2026-09-03
    2차 피드백으로 "카드 내부 1개 한정"에서 변경). 각 블록은 그 스티키의 `notes[]` 필드라
    분리·독립 이동이 불가능하고, hover 시 뜨는 ×로 개별 삭제 가능.
  - 스티키 배경색에 따라 텍스트 색(검정/흰색)이 WCAG **대비 비율**(검정·흰색 각각과 비교해
    더 높은 쪽 선택) 기준으로 자동 결정된다(`theme/palette.ts`의 `contrastInk`) — 단순
    "밝기 50% 기준"은 노랑 같은 파스텔에서 흰 글씨를 골라버리는 버그가 있어(2026-09-03
    2차 피드백으로 발견) 대비 비율 비교 방식으로 교체.
  - **화살표는 직선이 최적일 때만 직선**이고, 그 외에는 모서리가 둥근 직각 경로로 자동
    라우팅된다(`board/boardRouting.ts`) — 연결 포인트를 드래그하는 동안 어느 앵커에 붙을지
    미리보기 선(같은 라우팅 알고리즘)과 대상 앵커 하이라이트로 미리 보여준다.
  - 요소를 삭제하면 거기 연결된 화살표도 함께 삭제된다(고아 방지).
  - z-order(맨 앞으로/맨 뒤로), 마퀴 드래그로 스티키/이미지 다중 선택.
  - **색 필터는 마인드맵과 같은 상단 태그바**(`panes/TagBar.tsx`, 경로 바 바로 아래)에서 한다 —
    하단 플로팅 툴바가 아니다(2026-09-03 2차 피드백으로 이동). 보드도 `tagLabels`로 색별
    라벨을 붙일 수 있다(마인드맵과 동일 로직, `BoardDoc.tagLabels`).
  - 프레임·템플릿·투표·프레젠테이션 모드·실시간 협업 없음.
  - 리마인더 동기화 영향 없음(보드 요소는 `reminderOn/reminderId`를 갖지 않는다).
  - 파일 포맷: 완전히 새로운 포맷(`BoardDoc`, `version: 1`)이므로 기존 `.mind`/`.md` 마이그레이션은
    발생하지 않는다. 이미지 자산은 노트와 동일한 `images:write`/`images:read` IPC와 히든 폴더
    관례(결정 0010)를 그대로 재사용한다.

**v2 — 넓은 관계도 확장(2026-09-03, 실사용 피드백 "miro/freeform보다 압도적으로 실용적으로")**:

  - **키보드로 그래프 확장**: 스티키를 선택하고 방향키를 누르면, 그 방향에 이미 연결된
    스티키가 있으면 그리로 이동(탐색)하고 없으면 새로 만들어 연결한다(앵커 클릭과 동일한
    생성 로직 재사용) — 마우스 없이 화살표 구조를 계속 이어갈 수 있다. 선택한 스티키에서
    Enter는 편집 모드(화살표를 선택했으면 라벨 입력)로 들어간다.
  - **자동 정렬("정리")**: 하단 툴바 버튼 — 선택한 스티키에서 화살표의 `fromId→toId` 방향을
    따라 연결된 하위 트리를 BFS로 찾아 옆 열로 가지런히 재배치한다(`board/boardLayout.ts`).
    순환·다중 부모가 있는 그래프도 첫 방문만 유지해 무한 루프 없이 동작한다. 선택한 스티키
    자신의 위치는 고정, 하위만 이동한다. 마인드맵의 `layout/treeLayout.ts`(MindNode 전용,
    엄격한 트리 가정)는 재사용하지 않고 보드 전용으로 새로 작성했다 — 도메인 경계상 서로
    import할 수 없고, 보드 그래프는 트리를 강제하지 않기 때문.
  - **화살표 재배선**: 화살표를 선택하면 양 끝에 작은 손잡이가 나타난다. 손잡이를 다른
    스티키로 끌어다 놓으면 그쪽 앵커로 다시 연결되고, 빈 캔버스나 반대쪽 끝의 요소(자기
    자신과의 루프 방지)에 놓으면 취소되어 원래 연결이 유지된다. 앵커 드래그와 같은 스냅
    미리보기를 재사용한다.
  - **화살표 라벨**: 화살표를 선택하면 경로 중간(`boardRouting.ts`의 `pathMidpoint` — 꺾인
    경로도 시각적 중앙에 오도록 waypoint가 아니라 전체 길이 기준 중점)에 라벨 칩이 뜬다.
    라벨이 없으면 흐릿한 ＋로 추가를 유도하고, Enter나 클릭으로 인라인 입력에 들어간다.
  - **여러 스티키 일괄 편집**: 선택 툴바는 선택된 스티키가 1개든 여럿이든 뜨며(섞인 종류
    선택은 숨김), 색·모양·정렬·서식 변경이 선택된 모든 스티키에 한 번에 적용된다
    (`updateElements` — 한 번의 히스토리 단위 다중 패치). "텍스트 박스 추가"·"연동"은
    스티키 하나를 선택했을 때만 뜬다(대상이 모호해지는 걸 방지).
  - **보드 ↔ 마인드맵 연동**: 스티키는 마인드맵 노드나 노트 파일에 연동할 수 있다. 선택
    툴바의 "연동" 버튼(단일 선택만)에서 노드 검색 피커(`BoardNodePicker` — 현재 열린 맵
    탭만 검색, `note/NodePicker.tsx`와 동일한 UX·같은 스코프 제한을 board/ 안에 중복
    구현 — 도메인 경계상 note/를 import할 수 없어서)나 노트 검색/생성 피커
    (`BoardNoteLinkPicker`, 워크스페이스 전체 노트 인덱스 검색)를 연다. 링크는 노트↔노드
    시스템과 달리 **스티키 쪽에 저장되는 단방향 참조**다(`BoardStickyElement.nodeLink`—
    기존 `NoteLink` 타입 재사용,`.noteLink`— 새`BoardNoteRef`타입): 노트 파일이나 대상
    맵을 수정하지 않으므로 노트 쪽 역인덱스·삭제/이름변경 GC 훅이 필요 없다. 카드 안에
    작은 칩으로 표시되고, 누르면 그 노드로 이동(맵이 안 열려 있으면 열고 선택+스크롤,
    `board/boardLinks.ts`가 `note/noteLinks.ts`의 `revealNode`와 동일한 해석 로직을
    중복 구현) 하거나 그 노트를 오른쪽에 연다. ×로 연결만 해제(대상은 그대로 둠).
    대상이 삭제·이동되어 못 찾으면 토스트로 알리고 조용히 실패하지 않는다.

## 3. 범위에서 뺀 것 (Not now)

- 실시간 멀티플레이어 협업 (서버 없음 불변 조건과 충돌).
- 독립된 텍스트 박스, 일반 도형(스티키가 아닌 형태) — 스티키노트 하나로 통일(2026-09-03 재설계).
- 스티키 모양은 사각형·타원 2종만(깃발·말풍선 등은 2026-09-03 실사용 피드백으로 제외).
- 프레임/아트보드, 슬라이드 프레젠테이션 모드, 템플릿 갤러리, 투표/타이머.
- 손글씨/펜 드로잉(Apple Pencil 등 입력 장치 없음).
- 보드 요소의 리마인더 연동.
- 노드/노트 링크의 양방향 인덱스·GC 훅(대상 삭제 시 자동 정리) — 현재는 클릭 시점에 못 찾으면
  토스트로 알리고 사용자가 수동으로 연결 해제하는 지연(lazy) 처리만 한다(v2, 2026-09-03).
- 노드 검색 피커가 열린 맵 탭만 검색하는 제한(디스크의 닫힌 `.mind` 파일은 검색 안 됨) — 노트
  링크 피커의 기존 `NodePicker.tsx`와 동일한 제한을 그대로 물려받았다(v2, 2026-09-03).
- 정렬 스냅 가이드(구현 중 축소 — 마퀴 선택·리사이즈·앵커 연결로 핵심 조작은 충분히 커버됨).
- 이미지 드래그앤드롭·붙여넣기 삽입(구현 중 축소 — v1은 파일 선택 버튼만).
- undo/redo(마인드맵의 히스토리 스택과 별개 — 스티키·화살표 조작은 아직 되돌리기 대상이 아님).
