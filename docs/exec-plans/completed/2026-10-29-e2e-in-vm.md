# E2E를 숨은 macOS VM에서 실행
날짜: 2026-10-29
상태: completed

## 목표
배포 전 게이트(`make pre-release`)와 도메인 E2E를 이 Mac의 화면·키보드 포커스와 완전히 분리된 macOS VM 안에서 돌린다. 사람이 테스트를 기다리는 동안에도 다른 작업을 계속할 수 있게 한다.

## 범위 (포함 / 제외)
- 포함: Tart(Apple Virtualization 기반 VM 도구)로 만든 macOS VM, VM 준비·실행·정지 스크립트(`scripts/e2e-vm.sh`), `make` 타겟, VM 안에서는 quiet 모드를 끄는 E2E 헬퍼 분기, 운영 문서.
- 제외: 기존 로컬 E2E 경로(`make pre-release`, `make e2e-tag`) 변경. 그대로 둔다. GitHub Actions 변경 없음.

## 현재 상태
- 로컬 E2E는 같은 화면에서 창을 화면 밖(-3000,-3000)에 띄우고 앱을 `accessory`로 바꿔 포커스를 덜 뺏는다.
- macOS 26에서는 `accessory` 하에서 `win.focus()`가 실제 포커스를 못 옮겨 `@serial` 5개가 깨진다. 우회책 `CI=1`은 quiet 모드를 통째로 꺼서 창이 뜨고 포커스를 가져간다. 같은 화면을 나눠 쓰는 한 근본적으로 막을 수 없다.

## 가정
- Apple Silicon Mac, macOS 13 이상(Virtualization.framework, virtiofs 공유 폴더).
- Cirrus Labs 공개 이미지 `ghcr.io/cirruslabs/macos-tahoe-base`(관리자 admin/admin, 자동 로그인, Homebrew, Tart Guest Agent 포함).
- `tart exec`로 실행한 명령이 VM의 로그인 사용자 GUI 세션에서 Electron 창을 띄울 수 있다(검증 필요).

## 위험
- 디스크: 이미지 약 25GB. 이 Mac은 여유 52GB였다.
- 속도: VM은 CPU·메모리를 나눠 받아 로컬보다 느릴 수 있다.
- Tart 라이선스: Fair Source. 개인·소규모 사용은 무료(조직 사용 한도는 tart.run 라이선스 참고).
- Homebrew `cirruslabs/cli/tart` 수식이 2026-10 현재 brew 버전과 맞지 않아 설치 실패. GitHub 릴리즈(체크섬 확인)로 설치한다.

## 발견한 사실 (작업 중 갱신)
- Tahoe 기본 이미지는 압축 26.4GB, 이 회선에서 4~5.5MB/s(약 1.5시간). Tart는 받은 레이어를 따로 캐시하지 않고 VM 디스크로 바로 푼다(두 배로 차지하지 않음).
- 내장 디스크 여유(52GB)가 부족하다는 사용자 판단으로 VM을 외장 SSD(Samsung T7, ExFAT)로 옮겼다. ExFAT은 sparse 파일·clonefile이 없어 VM 디스크가 50GB 통째로, 복제 시 100GB까지 차지하므로 T7 위에 APFS sparsebundle(`E2E_VM_BUNDLE`)을 만들고 그 안을 `TART_HOME`으로 쓴다. 스크립트가 실행 때 열고 끝나면 닫는다.
- `~/.zshrc`에 환경변수를 넣는 것은 권한 검사에서 막혀, 이 Mac 전용 값은 `~/.config/mindmap/e2e-vm.conf`(값만 읽음, 실행 안 함)에 둔다.

## 결정 변경 이력
- VM에서 처음 돌린 게이트가 드러낸 **앱의 실제 버그**: 자동저장이 저장 중 들어온 편집을 놓침(`markSaved`가 dirty를 꺼서 예약된 다음 저장 취소). 보드·맵·노트 Pane과 `sessionStore.flushTab`에 "저장 중 편집 있으면 dirty 유지" 방어 추가. 느린 VM 디스크가 드러냈지만 빠른 Mac에서도 길게 입력 후 닫으면 마지막 입력이 유실될 수 있었다.
- VM은 UTC라 달력 테스트가 어긋남 → setup이 호스트 시간대로 맞춤. 헤드리스 VM 화면은 1024x768 고정(`tart set --display`·`--vnc-experimental` 모두 무효, 후자는 호스트에 Screen Sharing을 띄움) → 테스트 전용 enableLargerThanScreen.
- 호스트 스왑이 거의 찬 상태(≥10GB)면 VM이 느려져 30초 타임아웃이 난다 → VM 메모리 8GB, 테스트 전 안 쓰는 앱 종료 권장.
- 고정 `waitForTimeout(1_100)` 후 디스크를 읽는 보드 테스트 5개를 조건 대기(`waitForSaved`·파일 poll)로 교체.
- 남은 flaky(재시도 통과): flow-moves 새 노트 메뉴, note-rename-image-paths — 원인 미조사.
